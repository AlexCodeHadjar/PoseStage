# PoseStage

Полноэкранный просмотр PNG-поз на белом 3D-подиуме. Windows 11 x64.

Репозиторий содержит исходники, локальные библиотеки, тесты и превью. Исходные PNG-позы,
собранный EXE и автономный WebView2 хранятся отдельно от Git. Для запуска из репозитория
следуйте разделу «Запуск из исходников» и укажите свою папку поз. Снимки исправленного
размещения находятся в `previews/`.

## Готовая программа

Готовая поставка находится в `PoseStage-Portable.zip`, полный исходный код — в `PoseStage-Source.zip`.
Распакуйте Portable целиком, сохранив структуру папок.
Откройте `dist\PoseStage.exe` двойным кликом. Python, Node.js и интернет для работы не нужны.
В этой поставке рядом с EXE уже находится автономный Microsoft WebView2 в папке `WebView2`.
При переносе готовой поставки копируйте всю папку `dist`. Ничего устанавливать не нужно.
Если рядом с EXE нет `WebView2`, используется системный Runtime (обычно уже есть в Windows 11).
Программа не устанавливает компоненты и не проверяет обновления. Пакет с Runtime занимает
около 725 МБ без сжатия: это ближайшая альтернатива неработающему системному WebView2
в проверенном окружении. Сам `PoseStage.exe` занимает около 20 МБ.

## Запуск из исходников

В папке проекта, с Python **3.12** в PATH:

```bat
python -m pip install -r requirements.txt
python app.py
build.bat
```

Результат сборки — `dist\PoseStage.exe`. Папка `web` и все библиотеки включаются внутрь EXE.
Сборка EXE не скачивает и не встраивает WebView2 Runtime. Автономный Runtime из готовой
поставки сохраняется рядом с EXE и автоматически обнаруживается при старте.
Для изолированной установки можно выполнить:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
build.bat
```

`build.bat` автоматически использует `.venv`, если она есть. Иной Python можно указать переменной
`POSESTAGE_PYTHON` (полный путь к `python.exe`). Сборка не скачивает JS и не требует Node.js.

## Папка поз и настройки

Поиск: сохранённая папка → папка EXE → исходный путь из задания → диалог выбора папки.
Файл позы: только `photo-123456__pose-01.png`, регистр не важен. Сортировка по имени,
поиск без вложенных папок; новые PNG появляются при следующем запуске.

Все настройки, кэш границ, состояние, профиль WebView2 и журналы находятся в
`%APPDATA%\PoseStage\`. В папку с позами программа ничего не записывает.

Для смены папки закройте программу и создайте или измените `config.json` с полем `poses_folder`, например:

```json
{"poses_folder": "D:\\Рисование\\Позы"}
```

Или удалите `config.json`: будет применён обычный порядок поиска. При отсутствии поз
появляются сообщение и кнопка «Выбрать папку…». Последний индекс хранится в `state.json`.

## Управление

- `→` / `D` / правая стрелка — следующая поза.
- `←` / `A` / левая стрелка — предыдущая поза.
- `F` / `F11` — полный экран.
- `Esc` — выход. Колесо мыши не меняет позу.

Стрелки и курсор скрываются через 2,5 секунды покоя. Переход занимает 0,66 секунды;
быстрое нажатие ускоряет текущий переход и сохраняет максимум один следующий шаг.

## Реализация

Three.js **r170**, локальные ES-модули и importmap; Pillow; pywebview/WebView2; PyInstaller.
AgX, bloom, виньетка, зерно и SMAA применяются только к студии. Фигура рисуется последним
проходом unlit sRGB с `toneMapped=false`, поэтому её цвета не проходят через AgX и эффекты.
Её отдельный невидимый дубль отбрасывает настоящую alpha-tested тень; цветовой и теневой
шейдеры используют одинаковое растворение. RGB исходных PNG не меняется.
Границы альфы `>8` и нижний контур определяют масштаб и опору. Для имеющихся 220 поз
заданы группы опоры: стопы, колени, сидячие/лежачие. Опорная область центрируется по
видимому эллипсу крышки и помещается внутри него с запасом. Сидячие и широкие позы
могут быть меньше 61% высоты окна: это необходимо, чтобы ладони, таз и ноги лежали
на подиуме, а не зависали за его краем. Новые изображения получают автоматическую
группу по пропорциям; для нестандартных новых поз её можно уточнить в
`web/scene/pose_support_modes.json` при следующей сборке.

Рисунок остаётся плоским и рисуется ортографическим проходом без изменения пропорций.
Камера студии сохраняет перспективу. Только невидимый теневой дубль учитывает глубины
нижнего контура: точки опоры его тени находятся на настоящей верхней плоскости.
Это заменяет прежнюю привязку одной нижней точки, которая давала эффект парения.

Предзагружаются текущая и по две соседние позы. Максимум семь текстур, вытеснение с `dispose()`.
В неактивном окне рендер останавливается. При низкой измеренной частоте отключается bloom
и постепенно уменьшается разрешение студии; карта теней остаётся 2048².
Фигура всегда рисуется в исходном разрешении canvas с учётом DPI Windows. Разрешение
постобработки ограничено 1920×1080: на больших экранах это экономит память и время GPU,
не уменьшая разрешение рисунка. В состоянии покоя шейдер фигуры не считает шум растворения.
Геометрия плоскости ограничена bbox с соответствующими UV: GPU не обрабатывает большие
прозрачные поля вокруг узких поз. Исходный PNG и его пиксели при этом не изменяются.
Отражение в полу, разрешённое в ТЗ как необязательное, не включено.

Приложение обслуживает только `127.0.0.1` на свободном порту. Случайный префикс URL,
список разрешённых PNG, запрет выхода из `web`, CSP и блокировка внешних переходов.
Фоновые сетевые функции WebView2 отключены; внешний HTTP(S) направлен на закрытый локальный
прокси, локальные ресурсы идут напрямую. В программе нет внешних URL загрузки ассетов.

Сведения о фактически выполненных проверках и ограничениях: `ACCEPTANCE.md`.
Лицензии компонентов: `THIRD_PARTY_NOTICES.md`, Three.js — MIT.

## Проверки

```bat
python -m unittest discover -s tests -v
dist\PoseStage.exe --self-check
```

`--self-check` проверяет ресурсы внутри EXE, SHA-256 Three.js, доступность WebView2 и чтение
поз без открытия окна. Результат записывается в `%APPDATA%\PoseStage\diagnostics.json`;
код возврата 0 означает успех. Эта проверка не измеряет FPS и не заменяет графический тест.
