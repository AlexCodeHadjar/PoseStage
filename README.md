# PoseStage

Полноэкранный просмотр поз-референсов на белом 3D-подиуме для художников. Windows 11 x64.
Коллекции папок, галерея миниатюр, фильтры, избранное и теги, зеркало, оттенки серого,
сетка пропорций, масштаб без потери резкости, компактное окно поверх редактора.

Репозиторий содержит исходники, локальные библиотеки, тесты и превью. Исходные PNG-позы,
собранный EXE и автономный WebView2 хранятся отдельно от Git. Для запуска из репозитория
следуйте разделу «Запуск из исходников» и укажите свою папку поз. Снимки исправленного
размещения находятся в `previews/`.

## Готовая программа

Готовая поставка находится в `PoseStage-Portable.zip`, полный исходный код — в `PoseStage-Source.zip`.
Распакуйте Portable целиком, сохранив структуру папок.
Откройте `dist\PoseStage.exe` двойным кликом. Python, Node.js и интернет для работы не нужны.
В этой поставке рядом с EXE уже находится автономный Microsoft WebView2 в папке `WebView2`.
При переносе готовой поставки копируйте всю папку `dist`. Ничего устанавливать не нужно.
Сначала используется системный WebView2 Runtime (обычно уже есть в Windows 11). Если он
не запускается, программа один раз перезапускается с автономным Runtime из папки `WebView2`
рядом с EXE и запоминает это до обновления системного Runtime. Если системный Runtime
работает, папку `WebView2` (≈ 705 МБ) можно не поставлять: достаточно `PoseStage.exe` (≈ 20 МБ).
Программа не устанавливает компоненты и не проверяет обновления.

## Запуск из исходников

В папке проекта, с Python **3.12** в PATH:

```bat
python -m pip install -r requirements.txt
python app.py
build.bat
```

Результат сборки — `dist\PoseStage.exe`. Папка `web` и все библиотеки включаются внутрь EXE.
Сборка EXE не скачивает и не встраивает WebView2 Runtime. Автономный Runtime из готовой
поставки сохраняется рядом с EXE и автоматически обнаруживается при старте.
Для изолированной установки можно выполнить:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
build.bat
```

`build.bat` автоматически использует `.venv`, если она есть. Иной Python можно указать переменной
`POSESTAGE_PYTHON` (полный путь к `python.exe`). Сборка не скачивает JS и не требует Node.js.

## Коллекции и настройки

Поддерживаются `.png .jpg .jpeg .webp` с любыми именами, включая вложенные папки
(папки, начинающиеся с `.` или `_`, пропускаются). Прозрачный PNG ставится на подиум
по силуэту, непрозрачные изображения — целиком. Сортировка естественная (`pose-2` < `pose-10`).

Папок-коллекций может быть несколько: галерея (`G`) → «Добавить папку…» (`O`),
переключение и удаление там же. При первом запуске без коллекций программа берёт папку
из прежнего кэша, а EXE — папку рядом с собой; иначе показывает «Выбрать папку…».
Положение в коллекции запоминается по имени файла, поэтому новые позы его не сбивают.

Все настройки, кэши, миниатюры, избранное, теги, ручные режимы опоры, профиль WebView2 и
журналы лежат в `%APPDATA%\PoseStage\`. В папки с позами программа ничего не записывает.

## Управление

`?` или `F1` — справка по всем клавишам прямо в программе.

| Клавиши | Действие |
|---|---|
| ← → / A D, Home / End | предыдущая / следующая, первая / последняя (с учётом фильтра) |
| F / F11, Esc | полный экран; Esc закрывает панель, иначе выход |
| G | галерея миниатюр: фильтры, поиск, теги, коллекции |
| S | избранное |
| 1 / 2 / 3 / 0 | опора: стопы / колени / сидя-лёжа / авто |
| [ / ] (Shift — шаг 10 %), \ | размер позы меньше / больше на 3 %, сброс к 100 % |
| O | добавить папку-коллекцию |
| H, V | зеркально, оттенки серого |
| L | сетка: трети → пропорции (8 голов) → выкл |
| колесо, + / −, Z | масштаб у курсора, сброс вида; при масштабе — перетаскивание |
| двойной щелчок | 1× ↔ 2,5× |
| T, C | поверх всех окон, компактное окно |
| B | фон: студия или своё изображение (размытие, затемнение) |
| P | параллакс за курсором: выкл → мягкий → сильный |

Быстрые нажатия ←/→ складываются: десять нажатий — один переход на десять поз.
Внизу показан счётчик «12 / 220 · имя файла»; с фильтром — «3 / 40 из 220».

## Реализация

Three.js **r170**, локальные ES-модули и importmap; Pillow; pywebview/WebView2; PyInstaller.
AgX, bloom, виньетка, зерно и SMAA применяются только к студии. Фигура рисуется последним
проходом unlit sRGB с `toneMapped=false`, поэтому её цвета не проходят через AgX и эффекты.
Её отдельный невидимый дубль отбрасывает настоящую alpha-tested тень; цветовой и теневой
шейдеры используют одинаковое растворение. RGB исходных PNG не меняется.
Все позы коллекции показываются с одним размером тела. Рост фигуры оценивается по площади
силуэта (альфа `>8`): площадь одного тела почти не зависит от позы, поднятая рука добавляет
высоту рамки, но не площадь. Стоячее тело занимает 61% высоты окна; сидячие и лежачие позы
поэтому ниже, как в жизни. Позу уменьшают, только если иначе её опоры (ладони, таз, стопы)
не помещаются на крышке подиума или фигура выходит за края экрана. Неточную оценку можно
поправить клавишами `[` / `]`; поправка сохраняется. Нижний контур определяет опору: для
имеющихся 220 поз заданы группы стопы / колени / сидячие-лежачие, любую позу можно
переопределить клавишами 1/2/3 (0 — авто). Новые изображения получают группу по пропорциям.

Рисунок остаётся плоским и рисуется ортографическим проходом без изменения пропорций.
Камера студии сохраняет перспективу. Только невидимый теневой дубль учитывает глубины
нижнего контура: точки опоры его тени находятся на настоящей верхней плоскости.
Это заменяет прежнюю привязку одной нижней точки, которая давала эффект парения.

Предзагружаются текущая и по две соседние позы. Максимум семь текстур, вытеснение с `dispose()`.
В неактивном окне рендер останавливается. При низкой измеренной частоте отключается bloom
и постепенно уменьшается разрешение студии; карта теней остаётся 2048².
Фигура всегда рисуется в исходном разрешении canvas с учётом DPI Windows. Разрешение
постобработки ограничено 1920×1080: на больших экранах это экономит память и время GPU,
не уменьшая разрешение рисунка. В состоянии покоя шейдер фигуры не считает шум растворения.
Геометрия плоскости ограничена bbox с соответствующими UV: GPU не обрабатывает большие
прозрачные поля вокруг узких поз. Исходный PNG и его пиксели при этом не изменяются.
Отражение в полу, разрешённое в ТЗ как необязательное, не включено.

Приложение обслуживает только `127.0.0.1` на свободном порту. Случайный префикс URL,
список разрешённых PNG, запрет выхода из `web`, CSP и блокировка внешних переходов.
Фоновые сетевые функции WebView2 отключены; внешний HTTP(S) направлен на закрытый локальный
прокси, локальные ресурсы идут напрямую. В программе нет внешних URL загрузки ассетов.

Масштаб и панорама работают через `setViewOffset` обеих камер: рисунок, подиум и тень
увеличиваются вместе в полном разрешении, а размещение позы считается по исходной проекции.
Фронтенд разделён на ядро (`web/main.js`, `web/core/`) и UI-модули (`web/ui/artist.js`,
`web/ui/navigator.js`); контракты между ними и Python API — в `docs/API.md`.

Сведения о фактически выполненных проверках и ограничениях: `ACCEPTANCE.md`.
Лицензии компонентов: `THIRD_PARTY_NOTICES.md`, Three.js — MIT.

## Проверки

```bat
python -m unittest discover -s tests -v
dist\PoseStage.exe --self-check
```

`--self-check` проверяет ресурсы внутри EXE, SHA-256 Three.js, доступность WebView2 и чтение
поз без открытия окна. Результат записывается в `%APPDATA%\PoseStage\diagnostics.json`;
код возврата 0 означает успех. Эта проверка не измеряет FPS и не заменяет графический тест.

Тесты фронтенда (размещение, навигация, масштаб, интеграция с модулями) открываются в браузере:
`python -m http.server` из корня проекта → `tests/web/placement.test.html` (итог «PASS n / FAIL 0»).

Для разработки интерфейса в обычном браузере с настоящим Python API:

```bat
set APPDATA=%TEMP%\posestage-dev
python tools\dev_server.py --folder "D:\Позы"
```

Откройте напечатанный адрес и выполните в консоли страницы
`await import(location.pathname.replace(/web\/index\.html$/, '__shim.js'))`.
CI (`.github/workflows/ci.yml`) запускает тесты на Windows и собирает EXE для тегов `v*`.
